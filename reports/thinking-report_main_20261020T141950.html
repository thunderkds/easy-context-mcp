Decision

Problem: Which storage and embedding stack should easy-context-mcp use, given a shared Docker service, a stdio mode on the same files, one DB per project and a shared cache for worktrees?
Option B — One-File Path: one SQLite file per project with numpy search, a shared embed cache, and FastEmbed ONNX all-MiniLM-L6-v2 baked into the image.
It meets every PRD requirement with the fewest moving parts: one SQLite file per project gives isolation (FR-020), consistency during background jobs (FR-001b) and cheap orphan cleanup (FR-025); the shared embed cache makes worktrees cheap (FR-023); FastEmbed keeps the same model offline at a fraction of the image size and RAM (FR-011, NFR-001a). The only cost is a measured scale ceiling, and the VectorStore interface keeps Option C as a drop-in upgrade.
